### Syncthing 연결 문제 근본 원인 해결
- 증상: `raspberrypi` ↔ 노트북(`juhyeok`) 기기 간 "연결 끊김"이 몇 주간 반복됨
- 1차 시도(주소를 dynamic → Tailscale IP 고정)로는 해결 안 됨, 에러 로그 확인 결과
  `"remote expects to exchange encrypted data, but is configured for plain data"`
  — 폴더 공유 클러스터 설정 자체가 양쪽에서 불일치했던 것이 원인
- 해결: 양쪽에서 `Sync` 폴더 공유를 껐다가 재공유 → 클러스터 설정이 재조정되며 정상화
- 파일 전송은 base64 인코딩 + SSH 붙여넣기로 우회했으나, 이 과정에서 긴 텍스트가
  중간에 깨지는 문제가 반복됨(heredoc 방식은 특수문자에서 계속 실패) → Syncthing
  정상화 이후 이 우회가 더는 필요 없어짐

## 3. 휴대 모드 모델 재탐색 및 최종 확정
Qwen3 4B(기본 하이브리드 빌드)의 `think:false`가 Ollama 직통 API에서도 먹히지
않는 문제(사고 루프 반복, 120초 타임아웃 반복)가 계속되어 대체 모델을 조사·실측함.

| 모델 | thinking | vision | 한국어 | 판정 |
|---|---|---|---|---|
| Gemma 4 E2B | - | 있음(문제) | - | ❌ (기존에 이미 폐기) |
| Qwen3 4B (기본) | 못 끔 | 없음 | - | ❌ |
| Phi-4-mini (3.8B) | 없음(설계상) | 없음 | 심각한 오류
  (사실 오류, 존재하지 않는 단어 생성) | ❌ |
| Qwen3.5 4B | 있음 | **있음** | 미실측 | ❌ (capabilities 확인 단계에서 배제) |
| **Qwen3 4B-instruct** (`qwen3:4b-instruct`) | **기본 꺼짐**(capabilities엔 표시되나 실제 기본 동작은 비활성) | 없음 | 정확함 | ✅ **채택** |

- Qwen3 진영이 하이브리드 thinking 토글을 폐기하고 Instruct/Thinking 빌드를
  분리하는 추세라는 조사 결과와 일치 — `qwen3:4b-instruct`는 "이전 non-thinking
  모드의 업데이트 버전"으로 공식 설명되며, 실측으로도 사고 과정 없이 즉시 정확한
  한국어로 응답함을 확인
- 알려진 한계: 여러 자릿수 곱셈 등 다단계 계산에서 오답 발생(2×3×5×7×11×13×17×19를
  9,699,690이 아닌 6,469,693,230으로 계산 — 29까지의 소수를 곱한 값과 일치, 존재
  하지 않는 항을 임의로 추가한 것으로 추정). 정확한 계산이 필요한 질문에는 신뢰
  하면 안 됨

## 4. `ai-safe.sh` 기능 확장
- **대화형 모드** 추가: 인자 없이 실행하면 REPL처럼 여러 턴 이어서 대화 가능,
  맥락(이전 질문·답변) 유지 확인됨
- **대화 저장/재개**: `~/.ai_history/current.json`에 영구 저장, 재실행 시 이전
  대화 이어할지 자동으로 물어봄
- **`ai new`**: 새 대화 시작, 기존 대화는 `~/.ai_history/archive/`에 타임스탬프로 보관
- **`ai list`**: 보관된 과거 대화 목록을 번호·날짜·마지막 질문과 함께 표시
- **`ai resume <번호>`**: 목록에서 골라 다시 현재 대화로 불러와 이어감
- **단발 모드**: `ai "질문"`처럼 기존 방식도 그대로 지원(스크립트 등에서 활용 가능)

### 트러블슈팅: 대화 저장 시 UnicodeEncodeError
- 초기 구현은 bash 변수 치환으로 파이썬 소스 코드 안에 사용자 입력·모델 응답을
  직접 끼워 넣는 방식(`'''$VAR'''`)을 사용 → 스트리밍 중 한글 멀티바이트 문자가
  토큰 경계에서 깨지면서 유효하지 않은 서로게이트(surrogate)가 생성되어 저장
  단계에서 `UnicodeEncodeError`로 전체 실패, 대화 기록이 통째로 유실됨
- 해결: 사용자 입력·모델 응답을 전부 임시 파일로 저장했다가 파이썬이 파일에서
  읽어오는 방식으로 전환, 모든 파일 입출력에 `errors='replace'` 지정 → 깨진 문자가
  나와도 그 부분만 대체되고 전체 저장은 실패하지 않도록 함
