# 프로젝트 차별화 컨셉

> ⚠️ 이 문서는 2026년 6월 초기 설계를 담고 있습니다. 중간발표 피드백을 계기로
> 2026년 8월 AI/소프트웨어 계층 정체성을 재정립했습니다. 전체 경위는
> [`2026-08-ai-layer-redesign.md`](./2026-08-ai-layer-redesign.md) 참고.

## 한 줄 정의
> 로컬 AI를 탑재한 주머니 사이즈의 휴대 단말. 다른 기기와 자료를 주고받을 때 카톡 등 외부 서비스 대신 안전한 직접 통로(Tailscale)를 통해 통신한다.

---

## 핵심 정체성
- **본질**: 주머니에 들어가는 로컬 AI 핸드헬드 단말
- **프라이버시 원칙**: 기본은 차단, 의도적으로만 열린다
- **인트라넷의 역할**: "서버"가 아니라 "안전한 자료 이동 통로"

### 정체성 재정립 (2026-08)
중간발표에서 소프트웨어 스택이 "노트북에서도 재현 가능한 기성품 조합"이라는
지적을 받았습니다. 이를 반영해 차별점을 다음과 같이 재정의했습니다.

- **AI는 범용 채팅형 비서 단일 역할**로 명확히 함. 처음에는 "AI가 대화 중
  민감정보 입력을 감지·경고"하는 감시자 기능도 검토했으나, 로컬 AI의
  핵심 가치("외부 전송이 없으니 민감정보를 자유롭게 입력해도 된다")와
  논리적으로 충돌해 폐기했습니다. 실제 위협(로그 저장, RAG 인덱스 잔존,
  화면 노출, 클립보드 잔존)은 AI가 아닌 비-AI 보안 기능들이 담당합니다.
- **하드웨어 결합 요소를 차별점으로 명시**: 전원 종류 기반 모드 자동 판별,
  배터리 보호 회로, 킬 스위치처럼 노트북에서는 재현 불가능한 부분을
  프로젝트의 실질적 차별점으로 강조합니다.

## 설계 최우선 제약: 주머니 사이즈
- **평면**: 라즈베리파이 5 기판 크기(85×56mm) 기준 유지
- **두께 목표**: 40~50mm (재킷 주머니/가방 앞주머니 수납 가능)
- 스마트폰처럼 얇게는 비현실적 — USB-A 포트(15mm) + 액티브 쿨러 + 배터리 + 디스플레이 적층 시 물리적 한계. "주머니 수납 가능"을 1차 목표로 설정.

### 초소형화 설계 (확정)
- 디스플레이: **DSI 3.5인치 터치스크린**
- 전원: **LiPo 605080 + FM5324HJ1** (Plan A로 최종 확정 — 초기 계획이었던
  LiPo 3000mAh+IP5305T 조합에서 변경됨)
- 입력: 보유 중인 블루투스 키보드 활용 (내장 키보드 없음)
- 쿨러: 공식 액티브 쿨러 높이가 케이스 두께 기준
- 배선: 커넥터 대신 납땜 직결로 부피 절감

### 트레이드오프 (인지 필요)
- 화면 작음 → 긴 텍스트 입력/표시 불편 → 터미널+API 방식, 음성/단축 명령으로 보완 가능
- 배터리 제약 → 휴대 모드는 단시간 사용 전제, 텍스트 전용 소형 모델(Qwen3 4B)로 부담 최소화
- 발열 집중 → 작은 케이스일수록 방열 설계 중요
- 적층 구조 → 분해/수리 어려움 → 조립 순서 신중히

## 운영 모델 (단계적 확장)

### 1차 완성 — 핸드헬드 단독 + 자료 주고받기 (완료)
- 휴대 모드 단독 사용 (배터리 구동), 로컬 AI를 핸드헬드 자체에서 사용, 외부 인터넷 연결 불필요
- 다른 기기와 자료 주고받을 때만 무선 활성화 → SCP/SFTP로 직접 전송, 카톡 등 외부 서비스 미경유
- 24시간 서버 운영 없음: 전원 종류로 자동 판별해 필요할 때만 무선 허용

### 2차 확장 — 거치 서버 모드 (구현 완료)
- 전원 종류(3A/5A) 자동 감지로 거치 여부 판별 (초기 계획인 이더넷 감지 방식에서 변경)
- 외부에서 폰/노트북/태블릿으로 집 핸드헬드의 AI 접속
- 프라이버시 원칙 유지: 거치(의식적 행동) 없이는 외부 접속 차단, 우연한 외부 노출 없음

## 모델 운영 전략 (2026-08 갱신)

### 모드별 모델
| 모드 | 모델 | 역할 |
|---|---|---|
| 휴대 | Qwen3 4B (전환 중) | 빠른 QA·메모, 텍스트 전용 |
| 거치 | Qwen3 8B | 복잡한 추론·긴 문서 |

- 모델 교체 이력: Llama 3.2 3B → Qwen 2.5 3B → Gemma 4 E2B → **Qwen3 4B**
- 재선정 기준: 긴 컨텍스트/RAG 적합성(최우선) > 메모리·속도·시스템프롬프트
  순응도(공동 2위) > 한국어 처리 품질(최하위)
- Ollama 자동 관리: 미사용 시 RAM에서 자동 해제
- 수동 전환: `ollama run` 명령어 또는 alias (`ai` / `ai-smart`)
- ⚠️ 동시 실행 금지: 두 모델 동시 실행 시 RAM 초과로 시스템이 멈추거나 SSH
  연결이 끊길 수 있습니다 → 전환 시 `ollama stop <모델명>` 필수

### 왜 Gemma 4 E2B에서 교체했는가
"E2B"라는 이름은 총 파라미터가 아니라 유효 연산량 기준입니다. 실제 총
파라미터는 5.1B이며 vision/audio/tools/thinking capability를 텍스트 전용
사용에도 상시 포함해, 문서 스펙(약 5GB)보다 훨씬 큰 6.6GB+ 메모리를
사용했습니다. 이로 인해 반복적인 OOM(메모리 부족)이 발생했고, 심할 때는
기기 전체가 멈췄다가 재부팅되는 사고로 이어졌습니다(파일시스템 손상은
없었음). 텍스트 전용 구조인 Qwen3 4B로 교체해 이 문제를 해결했습니다.
자세한 트러블슈팅은 [`2026-08-ai-layer-redesign.md`](./2026-08-ai-layer-redesign.md) 참고.

## 보안 설계 (2026-08 재검토)

### 위협 모델 우선순위
1. **Tailscale 계정 탈취** — 가장 큰 단일 위협 → 강력한 비밀번호 + 2FA 필수
2. **SSH 비밀번호 무차별 대입** → SSH 키 인증으로 전환, Tailscale 인터페이스에서만 SSH 수신
3. **인터넷 직접 노출 금지** → 포트 포워딩 없이 Tailscale 안에서만 접근
4. **AI 대화·RAG 데이터 노출** — RAG 도입으로 새로 부상한 위협 (아래 참고)

### 부차적 위협 — 재평가됨
> ⚠️ **번복된 판단**: 이 문서는 원래 "분실/도난: 디스크 암호화는 불편함
> 대비 효용 낮음 → Tailscale 원격 차단 활용"이라고 서술했습니다. 하지만
> RAG 도입으로 개인 노트·수업자료가 한 폴더에 집중되면서 이 판단을
> **번복**했습니다. 현재는 gocryptfs 기반 RAG 폴더 암호화 + 휴대 모드
> 화면/세션 잠금을 함께 채택했습니다.
- AI 로그 평문 저장 → "라즈베리파이 자체 보안에 의존"하는 수동 방식에서,
  **로그 자동 삭제/만료 관리** 기능으로 자동화 확정(구현 예정)
- 같은 Wi-Fi 다른 기기: 집 Wi-Fi 비밀번호 강도로 충분 (변경 없음)

## 포트폴리오 서술 포인트
- 명확한 설계 철학: 프라이버시 우선 (기본 차단, 의도적 개방)
- 물리적 제약 하의 엔지니어링 트레이드오프: 주머니 사이즈 vs 성능/배터리/발열
- 하드웨어 + 소프트웨어 풀스택 통합: 회로(킬 스위치, 전원 감지) + 운영체제 + AI + 네트워크
- 단계적 확장 설계: 1차 완성 → 필요에 따라 +1/+2/+3 확장
- 실측 기반 의사결정: 모델 성능 측정 후 운영 방식 결정, **실측이 문서
  스펙과 다를 수 있음을 실제로 겪고 대응한 경험**(Gemma 4 E2B OOM 트러블슈팅)
- 실제 일상 운영: "만들고 끝"이 아닌 실사용 시스템, 발표 피드백을 반영해
  정체성을 다시 검토하고 근거를 재구축한 과정
